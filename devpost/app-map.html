A take-home guide to the proof of concept. Snapshot of the code at commit 9e2da2d; it can drift as the code changes.

What the app does

An exam platform for small tutors and coaching centres. A teacher turns a book PDF into an MCQ paper with AI, runs a timed exam for a student group using admit cards, then autochecks the papers to get scores, an AI report card per student, and a class view of who is struggling and on which chapters.

Main pieces
  • Teacher app (React + Tailwind, frontend/src/) — dashboard, groups, papers, exams, results.
  • Exam portal (frontend/src/pages/ExamPortalPage.jsx) — the student side, opened from the shared link.
  • API (FastAPI, backend/app/) — every rule: logins, timing, scoring, AI calls.
  • MySQL — groups, papers, exams, attempts, answers, reports.
  • OpenAI — chapter extraction, MCQ generation, student and class reports.

One action, end to end: “Autocheck” a student

Reference route (3 stops)

A reference route through the code behind the diagram. Search for the anchor in your editor.

  1. The button — frontend/src/pages/StudentResultPage.jsx, search async function autocheck. It posts to /exams/{examId}/results/{admitCardId}/autocheck and replaces the page data with the response, so the score and report card appear without a reload.
  2. The rules — backend/app/api/results.py, search def autocheck_student. Refuses if results are already marked complete (_ensure_unlocked) or the student never submitted, then calls _check_attempt, which scores the answers, asks for the report, and upserts the StudentReport row.
  3. Score in code, words from AI — backend/app/services/scoring.py score_attempt compares each selected option with the stored correct_option and builds per-chapter counts. backend/app/services/openai_client.py write_student_report sends only those results (chapters and missed questions) to OpenAI, so the AI explains the score but never decides it.
Why is the score computed in code and not by AI?

MCQ marking has one right answer, so code is exact, free, and repeatable. AI is reserved for what code can't do well: turning the numbers into a readable diagnosis (spec.md, “MCQ code scoring instead of AI grading”).

A practice to reuse

Check AI-generated output against the requirement, not just “it ran”.

At the early checkpoint, paper generation succeeded, but inspecting the actual generated questions through the API showed two problems a passing request hides: every question was worth 1 mark (so a “50-mark” paper summed to 3), and correct answers clustered on option A. One became a fix (marks = total ÷ questions), the other a recorded, deliberate deferral — both in devpost/checklist.md under Revisions.

On another project: whenever an AI step produces data (questions, summaries, classifications), look at a real sample and compare it with the acceptance criterion it is meant to satisfy. Then decide explicitly — fix now, or defer and write down why.
